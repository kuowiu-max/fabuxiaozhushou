## 3. 用消费者视角写得自然

- 默认一个标题、一段约 120–220 字的正文、最多三个有用话题。资料不足时缩短，不凑字数。
- 默认把写作者放在消费者的位置，像普通顾客向朋友分享消费信息。围绕“吃什么／买什么、怎么选、预算、分量、交通、适合什么场景”等实际关心的问题，按已核实资料选择两三个重点，不写商家宣传稿或百科式门店介绍，不要求每篇覆盖全部项目。
- 有用户提供的真实体验时，直接用第一人称写具体选择和感受，保留用户的偏好与实际评价，不刻意把所有内容写成好评。只有门店资料时，仍用消费者的选择、关注点和消费建议组织正文，可写“想吃……可以先看……”等有依据的表达；不要求补充体验才能起稿，也不把未发生的到店经历写成事实。
- 用日常说话的语气、具体事实和自然长短句；不使用机械的小标题堆叠、过量表情、重复排比或空泛总结。不要默认写“宝藏”“闭眼冲”“氛围感拉满”等套话。
- 围绕两三个已核实的门店细节展开，不逐项堆砌地址、品类和广告形容词。用具体名称与信息替代“品质卓越”“不容错过”“每一口都是享受”；没有依据的口味、服务或环境感受不补造。
- 默认一至两段，不固定套用“开头惊叹—环境—菜品—总结推荐”的顺序。标题自然具体，不默认夸张感叹号；不刻意加错别字、随机标点或虚构个人小故事制造真人感。
- 交付前在内部通读一遍，删掉重复信息、整齐排比、过量形容词和“总的来说”“无论是……还是……”等空泛收尾，只保留有用内容。用户要求“自然一点”时直接重写当前稿，不输出润色过程。
- 正文不写“作为 AI”“以下是为你生成的文案”“根据公开资料整理”等自我说明；只有影响交付的必要说明才放在正文之外，不默认附来源。文字风格不等于承诺通过 AI 检测，也不规避平台明确要求的内容标注。
- 原创表达，不直接复制帖子或评论，不把别人的评价改写成用户的亲身经历。消费者口吻可以表达选择和关注点；“我去了”“我点了”“吃起来”“亲测”“回购”等已发生的消费经历或感官体验必须来自用户真实描述，不靠外站评论补造。不虚构评分、消费、收入或分成效果。
- 用户说“小红书风格”时段落轻快、少量表情；说“大众点评／美团风格”时更直接，围绕已确认的产品与门店信息。用户说“只给正文”就只给正文。

## 4. 获取真实照片

- 从已核对门店的帖子或评论页发现实际公开的图片链接，优先环境、产品和门头，去重后默认取 3–6 张。少于三张时按实际数量交付，不伪造照片、不用 AI 图片冒充门店实拍。

# 图片获取与素材包（仅供有执行工具的 AI）

脚本由 AI 在其运行环境调用，不让用户本地部署。没有执行工具时使用该 AI 已有的图片／附件工具，或者提供真实来源链接。

## 下载已经发现的公开照片

先通过实际网页或浏览器工具发现照片链接、核对门店，写入 UTF-8 JSON：

```json
{
  "store": {"name": "已核对门店", "city": "城市", "branch": "分店"},
  "photos": [
    {"url": "从实际页面中取得的HTTPS图片链接", "source_url": "实际原帖或评论页面链接", "source_title": "来源标题", "caption": "已确认的照片用途"}
  ]
}
```

```sh
python3 /技能实际目录/scripts/fetch_photos.py --input /链接实际路径.json --output /新的照片目录
```

支持图片域名 `*.xhscdn.com`、`*.meituan.net`、`*.dpfile.com`，来源限小红书／美团／大众点评。仅支持标准 HTTPS，不接收登录凭据。最多获取六张，单张 10 MB、合计 50 MB，保留原始字节和出处。外站拒绝访问时记录失败，不绕过限制或猜照片链接。

退出码 0 表示至少取得一张照片，2 表示全部失败，1 表示输入或整体执行错误。必须读取 `照片来源.json` 和实际文件，再决定如何交付；不能将“尝试过下载”说成“已获取”。该文件只供 AI 核对成功数量及门店，不作为默认交付附件，不直接打包整个下载目录。

## 打包文案及实际照片

将照片结果中的 `images`、`sources` 与已写好的文案合并为 JSON：

```json
{
  "store": {"name": "门店名称", "city": "城市", "branch": "分店", "address": "已确认地址或留空"},
  "content": {"titles": ["自然标题"], "body": "依据已确认事实的原创正文", "tags": ["相关话题"]},
  "sources": [{"title": "来源标题", "url": "https://example.com/store", "notes": "实际读取的信息"}],
  "images": [{"path": "/实际存在的照片.png", "kind": "reference-photo", "source_url": "https://www.meituan.com/实际来源", "caption": "外站参考照片"}]
}
```

kind 可以是 `user-original`（用户原图）、`authorized-original`（授权原图）或 `reference-photo`（外站参考照片，必须有出处）。不可将参考照片误标为用户自有或授权原图。图片可以留空。类别只记录来源；`user-original` 不自动证明是本人到店拍摄，`authorized-original` 不自动满足分成活动的原创要求。下载脚本始终把外站图标为参考图，打包成功不表示符合活动资格。

```sh
python3 /技能实际目录/scripts/package_materials.py --input /记录实际路径.json --output /新的素材包.zip --content-only
```

输出不覆盖已有文件。默认使用 `--content-only`，只导出 `文案.txt` 和 `图片/01.png` 等编号照片，保留原始图片字节，不导出出处、来源文件、素材记录、输入 JSON 或本地原图文件名。下载与校验时使用的来源信息仅供内部核对，不要求用户保存。只有用户另行要求来源记录时才省略 `--content-only`，导出完整记录。脚本不会证明门店匹配或转载授权，AI 必须依据实际资料完成核对。
